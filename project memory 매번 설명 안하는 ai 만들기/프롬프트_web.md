# 프롬프트 (claude.ai Free)

같은 배경 설명을 매번 하지 않도록 **지침, 파일, 메모리** 세 곳에 나눠 담습니다. 끝나면 짧은 요청 한 줄로 팀 기준에 맞는 코드 리뷰가 나옵니다.

## 어디에 무엇을 담나

| 담는 곳 | 담는 것 | 예 |
|---|---|---|
| 프로젝트 지침 | 역할과 규칙 | 리뷰 순서, 답 형식, 모를 때 표시 |
| 프로젝트 파일 | 참고 자료 | 용어집, 리뷰 템플릿 |
| 메모리 | 나에 대한 맥락 | 공부 중인 스택, 답 언어 |

## 준비

- claude.ai **Free** 계정. 프로젝트는 최대 5개까지 만들 수 있으니, 자리가 없으면 쓰지 않는 프로젝트를 하나 정리합니다.
- 메모리는 Free 에서 기본으로 켜져 있습니다. **Settings › Your Claude** 에서 **Generate memory from chats** 가 켜져 있는지 확인합니다.
- 배포받은 `시연자료/` 의 파일 3개: `용어집.md`, `리뷰템플릿.md`, `order_view.py`
- 커넥터, 코드 실행, 유료 기능은 쓰지 않습니다.

**약속:** 이름, 연락처, 회사 코드, 계정 정보는 지침, 파일, 메모리 어디에도 넣지 않습니다.

## 만들기

### 1. 비교용 답 받기 (프로젝트 밖)

프로젝트 **밖**에서 새 대화를 열고 `order_view.py` 를 첨부해 보냅니다. 받은 답은 6단계에서 비교하므로 복사해 둡니다.

```text
이 함수 리뷰해 줘.
```

확인: 답의 순서와 형식이 정해져 있는가? 팀 규칙(소프트 삭제, 서비스 레이어)을 알고 있는가?

### 2. 반복 설명을 지침으로 바꾸기

같은 대화에서 이어 씁니다. 리뷰를 부탁할 때마다 덧붙이는 말을 지침으로 바꿉니다.

```text
나는 코드 리뷰를 부탁할 때마다 아래 설명을 반복해. 이걸 claude.ai 프로젝트 지침 한 문단으로 바꿔 줘.

- 반복하는 설명: [내가 매번 하는 설명 3가지]
- 지침에 꼭 들어갈 것: 역할(누구로 답하는지), 독자, 답의 순서와 형식, 근거를 대는 법, 모를 때 하는 일
- 길이: 6줄 이내. 용어 뜻과 템플릿은 지침에 넣지 말고 "프로젝트 파일의 용어집.md, 리뷰템플릿.md 를 따른다" 로 가리킨다
- 금지: 내가 말하지 않은 규칙을 지어내지 않는다. 이름, 회사명, 비밀번호 같은 정보는 넣지 않는다

끝나면 지침 문단만 코드 블록 하나로 보여 줘.
```

확인: "코드 잘 봐줘" 처럼 막연한 말이 남아 있지 않은가? 역할, 순서, 모를 때 규칙이 모두 있는가?

### 3. 프로젝트 만들고 지침과 파일 넣기

1. 왼쪽 메뉴의 **Projects** (또는 claude.ai/projects) 에서 **+ New Project** 를 누르고, 이름을 `{프로젝트 이름}` 으로 합니다. 이름과 설명은 Claude 가 읽지 않습니다.
2. **Set project instructions** 에 2단계에서 받은 지침을 붙여 넣고 **Save instructions** 를 누릅니다.
3. 오른쪽 프로젝트 지식 영역의 **+** 로 `용어집.md`, `리뷰템플릿.md` 를 올립니다. `order_view.py` 는 올리지 않습니다. 리뷰할 코드는 대화마다 바뀌는 재료이기 때문입니다.
4. 프로젝트 안에서 새 대화를 열고 입력합니다.

```text
이 프로젝트의 지침을 세 줄로 요약하고, 프로젝트 파일 이름만 목록으로 보여 줘. 파일 내용은 요약하지 마.
```

확인: 지침 요약이 내가 쓴 내용과 같은가? 파일 2개가 모두 목록에 있는가?

### 4. 나에 대한 맥락을 메모리에 맡기기

같은 대화에서 이어 씁니다. 리뷰 규칙은 지침에 있으니, 메모리에는 **나에 대한 것**만 남깁니다.

```text
이걸 기억해 줘.
- 나는 [공부 중인 스택] 기반으로 백엔드를 공부하는 신입 준비 개발자야
- 설명은 한국어로, 코드와 주석은 영어로 써 줘
- 개념을 설명할 때는 예시 코드를 먼저 보여 줘

무엇을 기억하기로 했는지 한 줄씩 보여 줘. 건강, 금융, 신분 정보처럼 민감한 내용은 내가 말해도 저장하지 마.
```

확인: 내가 말한 3가지와 같은가? 내가 말하지 않은 내용이 붙지 않았는가? 기억한 내용은 다음 대화부터 쓰입니다.

## 쓰기

### 5. 짧게 부탁하기 (프로젝트 안)

프로젝트 안에서 **새 대화**를 열고 `order_view.py` 를 첨부해 1단계와 **같은 문장**을 보냅니다.

```text
이 함수 리뷰해 줘.
```

확인: 설명을 덧붙이지 않았는데도 리뷰 템플릿 순서(버그 → 설계 → 스타일)로 나오는가? 용어집의 "소프트 삭제", "N+1" 을 짚는가? 근거가 부족한 의견에 "확인 필요" 가 붙었는가? 설명은 한국어, 코드는 영어인가?

### 6. 차이 비교하기

같은 대화에서 1단계에서 복사한 답을 붙여 넣습니다.

```text
아래는 같은 코드를 프로젝트 밖에서 리뷰한 답이야. 방금 네 답과 비교해서 차이를 표로 보여 줘. 열은 항목 | 프로젝트 밖 | 프로젝트 안 | 차이를 만든 곳(지침/파일/메모리) 이야. 두 답에 없는 내용은 지어내지 마.

[1단계에서 복사한 답]
```

확인: "차이를 만든 곳" 이 지침, 파일, 메모리로 나뉘어 있는가? 메모리라고 적힌 칸이 4단계에서 기억시킨 내용과 맞는가?

### 7. 메모리 점검하기

메모리는 저장하고 끝이 아니라 **보고, 고치고, 지우는 것**까지가 사용법입니다.

```text
지금 나에 대해 기억하고 있는 것을 모두 목록으로 보여 줘. 항목마다 이 프로젝트에서 저장한 것인지, 프로젝트 밖 대화에서 온 것인지 적어 줘. 확실하지 않으면 "모름" 이라고 써.
```

그다음 화면에서 직접 고칩니다. 채팅의 답보다 설정 화면이 기준입니다.

1. **Settings › Your Claude** 에서 **Your memory** 옆의 **Manage** 를 누릅니다.
2. **Topics** 에서 항목을 열고, 틀리거나 오래된 항목 1개를 연필 아이콘으로 고치거나 **Delete** 로 지웁니다.
3. 이 프로젝트를 계정 메모리와 분리하려면 프로젝트 페이지의 **Memory** 에서 **Use account memory** 를 끕니다.

확인: 새 대화에서 "나에 대해 기억하는 것 보여 줘" 를 보내, 지운 항목이 나오지 않는지 봅니다.

### 8. 안전 점검

```text
이 프로젝트의 지침과 파일, 그리고 네가 기억하는 내 정보에 이름, 연락처, 회사 내부 정보, 계정이나 금융 정보가 있는지 점검해 줘. 있으면 어디에 있는지만 알려 주고, 없으면 "없음" 이라고 써.
```

확인: 걸린 항목이 있으면 내가 직접 지침, 파일, 메모리에서 지웁니다.

### 9. 내 것으로 (추가 실습)

내가 자주 하는 다른 일(커밋 메시지, 기술 블로그 초안, 면접 답변 연습 중 하나)로 2~5단계를 다시 합니다. Free 는 프로젝트가 5개까지이므로 새로 만들기 전에 남은 자리를 봅니다.

산출물은 두 가지입니다.

- 지침 문단 1개
- 메모리 점검 결과 한 줄 (예: "예전 스택 Spring 항목을 지우고 Django 로 고침")
